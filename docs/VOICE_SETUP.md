## Implemented behavior

- The **Call** composer uses an approved business line. **Connect phone** prepares the phone; starting or accepting a call requests microphone access. The floating phone retains mute, timer and hangup controls across dashboard client navigation. A reload, closing the tab, network loss or device failure can interrupt a call; review its status before retrying.
- In browser mode, incoming calls ring up to ten explicitly approved, active, available teammates during configured business hours. Personal phone mode instead rings one approved teammate's mobile with press-1 acceptance; see the October 26 section below. A connected receive-capable browser publishes presence every 30 seconds; presence expires after 60 seconds. Outside hours or without available staff, the caller gets voicemail. Unanswered/busy calls fall back to voicemail. A signed staff-answer screening callback rechecks current membership, permissions and presence before bridging audio.
- Call activity and protected voicemail appear in the same relationship timeline as permitted email, SMS and notes. First outbound calls preserve the selected CRM contact/lead. Incoming callers can match a unique contact or lead; ambiguous/general callers remain separate. CRM linking never grants access to another channel. Hidden sources remain excluded from queue counts, ordering and previews.
- Voice grants are separate from SMS: read, outbound calling, incoming ringing and voicemail deletion. Workspace viewers cannot place/accept calls or delete audio. Playback and each action recheck live grants. Outbound calls require a two-minute durable intent bound to the signed browser identity, normalized destination, line, user and workspace. The browser passes only its opaque intent token; the server chooses the dialed number. Replays cannot place a second call.
- New call attempts are limited to 20 per teammate per line per hour and 60 per line per hour; repeated intent requests do not create another call. CRM call-channel blocks prevent dialing. Each connected call is capped at one hour. These safeguards do not replace monitoring actual provider usage and costs.
- Voicemail uses a disclosed greeting, beep and maximum three minutes, without automatic voicemail transcription. Connected-call recording/transcription uses the separate [recording pipeline](CALL_RECORDINGS.md). Voicemail playback verifies the recording's account, parent call, source and channel count, then proxies bounded MP3 through an authenticated route. No provider credentials, recording URLs or public storage links reach the browser. Deletion removes provider audio and retains the call entry.
- Audio is hidden after 90 days. The existing authenticated Search Console worker also attempts at most one leased voicemail deletion per invocation; reporting continues if voice maintenance fails. Failed deletions retry later, up to ten attempts. Operators must investigate exhausted retries and run the existing scheduled worker often enough to clear the expected volume. Provider retention/storage charges can continue until deletion is confirmed. Call metadata is retained separately from audio.

## Verification and limits

Local browser fixtures use only `ta_voice_browser_test` on loopback port 55433. They replace the browser SDK at development bundling time and intercept provider HTTP in the test process; production builds reject the fixture flag. These tests verify UI, authorization, signed callbacks and durable records without real WebRTC, audio or provider delivery. Provider acceptance above remains required. Run `npm run test:voice:browser` with the disposable local PostgreSQL service; do not run multiple Next browser suites concurrently against the same `.next/dev` directory.

Mobile browsers can lose audio/signaling when backgrounded or locked. The iOS companion currently wraps the website; this increment does not implement native iOS PushKit/CallKit or promise background ringing. Unsupported embedded browsers retain call history/voicemail access and should use a supported desktop browser for calling.

Remaining refinements include advanced escalation, missed-call follow-up automation and native mobile telephony. Connected-call recordings, transcripts, evidence-linked summaries and reviewed follow-up tasks are implemented. The owner has confirmed basic live operation; that does not establish every production access, retention or recovery scenario. Long-audio and speaker/timestamp limitations are described in the recording guide.

## Personal-phone incoming calls (October 26, 2026)

Settings > Calling & voicemail > Incoming call destination supports **Personal phone only**. Choose an active teammate who has Receive permission and enter their US mobile number. The setting does not change outbound CRM calling or recording/transcription preferences. Personal numbers are saved in authenticated settings, never in source control.

In this mode no browser clients are dialed. The configured mobile rings even when the dashboard is closed. The mobile sees the business number; answering plays "Tailored Agents call. Press 1 to accept." Only pressing 1 bridges customer audio. No answer, rejection, or personal voicemail answering without pressing 1 returns the caller to CRM voicemail. Calling from the forwarding phone itself does not loop back. A busy recipient goes to voicemail. Existing business hours still apply unless **Also forward outside business hours** is checked.

Twilio remains in the media path. The original customer identity, CRM conversation, answered-call recording callbacks, transcript/summary worker and client-memory pipeline remain the same. Forwarded minutes incur an additional outbound phone leg. Automated notes require the existing recording/analysis settings and worker; calls made directly to a personal number outside Twilio cannot be captured.

The number webhook stays `/api/integrations/twilio/voice/incoming` (POST). New signed `/forward-answer` and `/forward-accept` callbacks are generated automatically. The server snapshots the approved destination, verifies the provider child leg and rechecks current teammate permissions before bridging. Apply migration 0024 before enabling the setting. Existing lines default to browser mode; deployment does not silently change routing.

Acceptance: from a different phone, call the business number with the CRM closed, press 1 on the forwarding mobile, confirm two-way audio, then check the CRM recording and eventual summary. Repeat without accepting and confirm CRM voicemail, not personal voicemail. Calls outside configured hours follow the chosen setting.
